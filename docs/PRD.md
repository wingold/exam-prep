# 复习刷题产品 PRD（暂定名：考证刷题助手）

> 版本：v0.1（需求基线）
> 形态：Web 版（电脑浏览器免安装） + 安卓 APK
> 同步：本地优先 + WebDAV 免费同步（不租服务器、不买域名）
> 状态：待评审

---

## 1. 产品概述

### 1.1 背景与目标

用户正在备考职业资格证，需要一个覆盖「报考科目管理 → 系统复习 → 刷题练习 → 模拟考试 → 错题归档 → 成绩跟踪 → 考期倒计时」全链路的个人学习工具。市面现有产品（OpenExam、shiroha-quiz、Anki）各自覆盖其中一段，但没有一个把**考证进度台账**（考了几科、各科分数、下考期报考计划、复习完成度、倒计时）与刷题功能整合在一起。

本产品目标：

1. 一套代码同时交付 Web 版与安卓 APK，电脑端**零安装**；
2. 完全免费、离线可用、数据自主（本地存储 + 用户自己的网盘）；
3. 以「考证进度模块」为核心差异化，其余功能对齐成熟开源产品的已验证体验。

### 1.2 目标用户

- 单人自用为主（多设备：办公电脑 / 家里电脑 / 安卓手机），设计上不排除后续小范围分享题库。

### 1.3 竞品借鉴

| 竞品 | 借鉴点 | 不采纳处 |
|---|---|---|
| OpenExam（MIT） | 按卷模考/按模块专项、错因归类错题本、成绩报告与周对比、Word/Excel/PDF 导入、自定义模型 AI 讲题 | 桌面客户端形态（本产品电脑端用 Web）；手动 JSON 互导的同步方式 |
| shiroha-quiz（开源） | WebDAV 同步实践、Word/Excel/TXT/JSON 自动解析导入、Android APK + Web 双形态 | — |
| Anki（31.9k stars） | 间隔重复复习算法（SM-2/FSRS）、卡片式记忆 | 独立 App 形态；本产品仅在「复习记忆」模块内嵌该能力 |

### 1.4 名词定义

- **题库（Bank）**：一套题目的集合，对应一门科目或一份真题卷。
- **考期（Session）**：一次考试周期（如 2026 年 5 月考期），含考试日期与报考截止日。
- **台账（Ledger）**：考证进度模块中的科目/成绩/报考计划总表。
- **错因（ErrorReason）**：错题的人为归类标签。

### 2.3 考试模式

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| EXAM-01 | 整卷限时模考 | P0 | 按真题卷结构整卷作答，总倒计时，到时自动交卷 |
| EXAM-02 | 自定义组卷 | P0 | 两种模式：①按真题卷结构（默认，自考标准卷：单选 30×1 + 多选 5×2 + 名词解释 5×3 + 简答 5×5 + 论述 2×10 = 100 分，材料题不参与）；②自定义题量。缺题型时开始前明确提示缺几题，不静默少给 |
| EXAM-03 | 考试过程体验 | P0 | 答题卡导航、标记存疑题、剩余时间醒目提示、中途退出可续考 |
| EXAM-04 | 交卷评分 | P0 | 客观题自动判分；主观题交卷后进入「主观题自评」，逐题对照参考答案定档。得分 = 客观题 + 主观题自评折算（答对 100%、答一半 60%、没答出来 0%），同时给出卷面满分（题库题量不足时满分低于 100） |
| EXAM-05 | 考后报告 | P0 | 见 STAT-03 |

### 2.4 复习记忆（间隔重复）

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| SRS-01 | 记忆卡片 | P1 | 题干/知识点做成卡片，翻面看答案；「认识/模糊/不认识」三键评分 |
| SRS-02 | 调度算法 | P1 | **简化 SM-2**（不采用 FSRS，理由见下表注）：三档评分；`ease` 初值 2.5，按 −0.2 / −0.15 / 不变调整，下限 1.3；间隔阶梯 1 → 3 → ×ease，单卡封顶 365 天；叠加**考试日封顶**（`min(间隔, 距最近考期天数 ÷ 3)`，只压不拉）。实现见 `src/srs.js` |
| SRS-03 | 每日复习任务 | P1 | 首页展示今日待复习 N 张 + **未来 7 天负载图**（逾期并入今天），完成打卡 |
| SRS-04 | 错题自动入队 | P1 | 做错的题自动进入记忆队列，**次日 0 点**到期（当日做错当日不再重考，避免与错题本重复）；已在队列的卡答错则按「不认识」重排并扣易度，手动加卡不扣；设置页提供**总开关**（本机偏好，不参与同步） |

> **为什么不用 FSRS**：FSRS 用 D/S/R 三量建模、依赖大量真实复习日志预训练参数，收益要在卡片上千张、复习跨半年以上才明显。本项目题库规模在几百量级、备考周期数月、教材范围固定，落在 SM-2 的低收益区间；移植 FSRS 需引入参数拟合与大量边界处理，维护成本远高于收益。故采用简化 SM-2，并在注释与本文档中固定取舍。
>
> **排期唯一来源（方案 A）**：记忆队列（`db.cards`）是唯一的调度依据，错题本只负责收录、标错因与展示。
>
> - 「掌握」＝ 卡上 `reps ≥ 4`（连续 4 次没答错）**或** `intervalDays ≥ 21`。用「或」是必要的：叠加考试日封顶后间隔会被压在「距考试天数 ÷ 3」，临近考试时可能长期停在 13 天，只按间隔判定会让错题永远移不出去。
> - 答错（无论来自练习、模考还是错题重做）→ 卡被打回 1 天 → 错题自动回到「待复习」，不需要另立一套「连对次数」。
> - 手动「标记掌握」写入 `clearedBy = 'user'`，不参与自动回收。
> - 没有卡的错题保持原状态不动，避免历史数据被一次性翻回待复习。

## 3. 数据模型（核心实体）

```
Certificate   证书档案
  id, name, org, createdAt

Subject       科目
  id, certificateId, name, passScore, sortOrder
  status: NotRegistered | Registered | Passed | Failed
  scores[]: { sessionId, score, passed }

ExamSession   考期
  id, certificateId, name, examDate, registerDeadline

Registration  报考记录
  id, sessionId, subjectIds[]

Bank          题库
  id, subjectId?, name, source(导入文件), questionCount

Question      题目
  id, bankId, type, stem, options[], answer, analysis, chapter, difficulty?

Attempt       作答记录
  id, questionId, mode(practice|exam|review), chosen, correct,
  wrongReasons[], durationMs, at

Paper         组卷/整卷
  id, bankId | rule, questionIds[], timeLimitSec, score?

PaperResult   考试结果
  id, paperId, score, totalScore, durationSec, at, perChapter{}

ReviewCard    记忆卡片（间隔重复）
  id, questionId, dueAt, stability, difficulty, lastRating

WrongItem     错题本条目
  id, questionId, wrongReasons[], wrongCount, rightStreak,
  status: Active | Cleared | Archived

SyncEnvelope  同步文件
  schemaVersion, deviceId, updatedAt, payload(上述实体的增量/全量)
```

### 3.1 倒计时规则

- `距考试天数 = examDate - today`；若同考期存在多个科目，取最近的 `examDate`。
- `距报考截止 = registerDeadline - today`，截止前 7 天在总览高亮提醒（端内，不做推送）。

### 3.2 科目状态机

```
NotRegistered --报考--> Registered --成绩>=合格分--> Passed
                         Registered --成绩<合格分--> Failed
Failed --下次考期再报--> Registered
```

### 3.3 考试报告对比口径

- 单次报告与「个人近 5 次同章节正确率」「历史平均分」对比；
- 周对比口径：本周有作答的章节 vs 上周同章节，正确率下降 ≥ 10 个百分点标记为退步。

### 3.4 科目复习进度算法（可调参数）

```
复习进度 = 40% × 章节覆盖率
         + 30% × 错题清空率（已 Cleared 的错题 / 总错题）
         + 30% × 近期正确率达标（近 7 天该科正确率 ≥ 目标线 70% 记满分，线性折算）
```

- 未开始任何动作的科目进度为 0%；
- 参数开放设置页调整；
- 数据不足（如无近 7 天作答）时该项记 0，不造假。

## 4. 同步架构（WebDAV 免费方案）

### 4.1 总体原则：本地优先

- 所有读写先落本地（Web：IndexedDB/Dexie；APK：同一套 IndexedDB，Capacitor WebView 内行为一致）；
- **APK 端 100% 离线可用**（Web 资源随包内置，无网络亦能完整使用）；
- **Web 端已具备离线能力**：首次联网加载后由 Service Worker 缓存外壳与静态资源，断网仍可打开与刷题；首次访问仍需联网。
- 同步是异步增强，失败不影响使用。

### 4.2 同步流程

1. 用户在设置页填 WebDAV 地址（如坚果云 `https://dav.jianguoyun.com/dav/`）、账号、密码（或应用密码）；
2. 端侧生成 `sync.json`（SyncEnvelope）上传至网盘指定路径；
3. 触发时机：
   - 打开应用后 2.5 秒（等首屏可交互）；
   - **作答后延迟 20 秒合并触发**：期间连续答题只会重置计时器，不重复上传；交卷后 10 秒触发；应用切到后台时立即补发；
   - 应用在前台时每 30 分钟一次；
   - 设置页手动「立即同步」。
4. 每次同步的动作：
   - 下载远端 envelope，与本地按**记录级 `updatedAt` 时间戳**合并（last-write-wins）；
   - 实体以 id 唯一，新增记录直接合并，冲突记录取较新者；合并写入本地用 `bulkPut`，**只增不删**（空设备拉取不会清空云端）；
   - 合并后上传新 envelope。
5. **失败必须可见**：上次成功同步时间与最近一次失败原因写入本地，侧栏页脚 / 手机「更多」面板 / 设置页三处可查；超过 3 天未成功同步高亮提醒。
   （原计划的「同步冲突暂存」未实现，冲突时不留副本，较旧的一方直接被覆盖。）

### 4.3 CORS 问题与代理

- 浏览器直连 WebDAV 需要对方返回 CORS 头，多数网盘不保证；
- 方案：优先直连 → 失败则走 **Cloudflare Worker 免费代理**（用户自部署，5 分钟配置，转发 WebDAV 请求，凭据仅在端侧与用户 Worker 之间流转）；
- Worker 不存储数据、不做账号体系。

### 4.4 明确不做

- 不做多用户实时协同编辑；
- 不做服务端账号系统；
- AI API Key 不进同步文件。

## 5. 非功能性需求

| 类别 | 要求 |
|---|---|
| 离线 | APK：除「AI 讲题 / 同步」外全部离线可用；Web：首次联网加载后离线可用（PWA） |
| 性能 | 1 万题题库导入 < 10s；翻题、判分操作 < 100ms；首屏可交互 < 2s |
| 数据自主 | 一键全量导出；删除应用前数据可完整带走；无埋点、无注册登录 |
| 隐私 | 不上传任何学习数据到第三方（用户自己的网盘与模型服务除外） |
| 兼容 | Web：Chrome/Edge/Firefox 最近两个大版本；Android 8.0+；iOS 暂不覆盖（PWA 可部分兜底） |
| 内容合规 | 内置题库仅收录公开真题，注明来源，仅供个人备考 |

## 6. 界面结构（信息架构）


## 8. 风险与开放问题

1. **PDF 解析**是导入功能最大不确定性，扫描版依赖 OCR；M1 先不做，格式规范先行。
2. **WebDAV CORS** 需实测坚果云行为；兜底 Worker 方案已列入，需用户自部署一次。
3. **Web 版国内访问**：静态托管若用 GitHub Pages 在国内不稳，备选 Cloudflare Pages 或干脆「本地文件 + PWA」分发；正式分享再考虑域名（那才需要公网/域名/备案）。
4. **iOS**：暂不原生覆盖，PWA + Safari 可基本使用，待定。
5. **倒计时/进度推送**：不申请通知权限，首屏展示即可；如需系统级提醒，P2 再评估。
6. **产品名称**待定。

## 附录 A：导入格式规范（JSON）

```json
{
  "version": 1,
  "bank": { "name": "XX证-科目一", "subject": "科目一" },
  "questions": [
    {
      "type": "single",
      "chapter": "第一章",
      "stem": "题干文本",
      "options": ["A选项", "B选项", "C选项", "D选项"],
      "answer": ["A"],
      "analysis": "解析文本"
    }
  ]
}
```

Word/Excel 导入以该结构为归一化目标，解析失败的题目进入「待人工确认」列表而非直接丢弃。

### A.1 type 取值

| 取值 | 题型 | options | answer | 判分 |
|---|---|---|---|---|
| `single` | 单选题 | 4 个 | 1 个字母，如 `["B"]` | 自动 |
| `multi` | 多选题 | 4-5 个 | 2 个以上字母，如 `["A","C"]` | 自动（错选/多选/少选均不得分） |
| `judge` | 判断题 | 留空（自动补「对/错」） | `["对"]` 或 `["错"]` | 自动 |
| `fill` | 填空题 | 留空 | 1 个字符串 | 自动（忽略大小写，包含即算对） |
| `term` | 名词解释 | 留空 | 1 段定义（推荐） | 自评 |
| `short` | 简答题 | 留空 | 分点写，如 `["（1）…","（2）…"]` | 自评 |
| `essay` | 论述题 | 留空 | 先要点后展开说明 | 自评 |
| `material` | 材料题 | 留空 | 结合材料分点作答 | 自评 |

导入时 `null` / 缺省 `type` 按单选题处理；`名词解释题`、`案例分析题`、`单项选择题` 这类全称写法会自动归一化。
