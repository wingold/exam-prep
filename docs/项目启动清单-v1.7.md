## 一、项目基本判断

### 1.1 当前事实

| 项目 | 实际情况 |
|---|---|
| 项目名称 | 考证刷题助手（exam-prep），应用名「考证刷题」，包名 `com.examprep.app` |
| 形态 | Vue 3 + Vite 网页版 + Capacitor 安卓 APK，一套代码双端 |
| 代码规模 | `src/` 25 个文件，9 个页面 + 2 个组件 |
| 数据层 | IndexedDB（Dexie）本地优先 + WebDAV 记录级合并同步 |
| 当前版本 | v1.6.1，已连续产出 v1.2 → v1.6.1 共 6 个 debug APK |
| 文档 | `README.md`（完整）+ `docs/PRD.md`（v0.1 基线）+ `release-notes-v1.6.md` |
| 版本管理 | Git 共 4 次提交，最后一次 `47b068a`；`release-notes-v1.6.md` 未入库 |
| 测试 | 无任何自动化测试文件 |

### 1.2 核心判断（据 D1 修正）

**这不是从零启动，而是「从能自己用」到「能稳定自己用、顺便让别人也能用」的二次启动。**

定位为自用后，原先按商业交付列的要求要往下调：不需要多设备兼容矩阵、不需要上架、不需要运营级稳定性。但有两件事反而变得**更不能省**：

1. **签名密钥**。自用的核心诉求是"覆盖安装不丢数据"。没有固定 keystore，每换一次签名就得卸载重装，`IndexedDB` 数据全没。而一旦公开让别人下载了你的包，再换密钥就会导致所有已安装用户无法升级——**第一个公开的 APK，必须是最终签名签的**。
2. **版本号递增**。现在 `versionCode` 恒为 1，意味着新包装到手机上可能不触发升级，只能靠卸载重装，又回到丢数据的问题。

网页版那侧，既然是自用 + 挂 GitHub Pages，**PWA 的价值比我原先估的高**：手机浏览器加到桌面、断网也能刷题，等于免掉装 APK 这一步。

### 1.3 本期真正要解决的四个问题

> 让"每次迭代都能安全覆盖升级、换设备能带走数据、没网也能刷题"这三件事成立，再谈新功能。

## 四、实施路径（里程碑制）

```
M0 仓库收口 → M1 签名与版本 → M2 PWA 与 Pages → M3 题库导出 → M4 考试续考 → M5 回归与文档
```

**设计原则**：每个里程碑结束时项目都处于"可停可交付"状态。做完 M1 就可以长期停在那儿用；M3/M4 可以调换；M5 可以拆散了随手做。

| 里程碑 | 目的 | 出口条件（做到这几条就算完） |
|---|---|---|
| **M0 仓库收口** | 起点干净 | 工作区无未跟踪的散落文件；密钥/题库有 ignore 规则；`npm run build` 一把过 |
| **M1 签名与版本** | 能安全升级 | `assembleRelease` 出包；覆盖安装 v1.6.1 后数据完整；versionCode=7 / versionName 1.7.0 |
| **M2 PWA 与 Pages** | 网页版能离线 | 断网可进首页、可刷题；Chrome 出现"安装"；Pages 链接在手机上打开正常 |
| **M3 题库导出** | 题库能带走 | 导出文件在另一浏览器导入，题量/答案/章节/重点全对 |
| **M4 考试续考** | 模考不白做 | 考试中杀进程，重进提示恢复，答案与剩余时间保留 |
| **M5 回归与文档** | 改坏能发现 | `npm test` 全绿；PRD 每条有状态；发布说明写清 |

### 4.2 发版流程（每次发布照做，别跳步）

v1.7 发布时漏了打 tag，结果提交全在远端、GitHub 上却看不到这一版。原因是流程里只有"出包"，没有"标记版本"。固化成七步：

| 步 | 动作 | 检查点 |
|---|---|---|
| 1 | 只改 `package.json` 的 `version` | 别手改 `build.gradle`，它自动派生 |
| 2 | `npm run build` → `npx cap sync android` → `npm run check:assets` | 校验不过就停，否则打出的是旧界面 |
| 3 | `JAVA_HOME=/d/jdk21/... ./gradlew assembleRelease` | 必须 JDK 21 |
| 4 | `apksigner verify --print-certs` + `aapt2 dump badging` | 证书 SHA-256 与 `CREDENTIALS.txt` 一致；versionName / versionCode 正确 |
| 5 | 归档 `release/考证刷题-vX.Y.Z-release.apk`，提交并 `git push origin main` | 工作区干净、`origin/main` 追平 |
| 6 | `git tag -a vX.Y -m "..."` → `git push origin vX.Y` | **最容易漏**：不推 tag，GitHub 上就没有这一版 |
| 7 | `gh release create vX.Y <附件> --title "vX.Y 简述" --notes-file release-notes-vX.Y.md` | 附件名用 ASCII `exam-prep-vX.Y.Z-release.apk`；正文去掉首行 H1（标题已含版本）；创建后核对附件 sha256 与本地一致 |

> 命名对照：tag 用短形式（`v1.6.1`、`v1.7`），APK 内部 `versionName` 用三段式（`1.7.0`），Release 标题为「版本 + 一句中文说明」。
